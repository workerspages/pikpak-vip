# PikPak VIP 自动邀请程序 (Docker 优化版)

基于 Python 和 PyWebIO 编写的 PikPak 临时会员自动邀请程序。通过提供网页端 UI，配合微软邮箱自动接收验证码，实现 PikPak 邀请奖励的自动化获取。

* **原作者**：B站纸鸢的花语
* **二改作者**：非雨
* **当前优化版**：针对 NAS 和云服务器 Docker 部署进行了深度重构与修复。

## ✨ 版本更新说明 (当前优化版)

此版本在原版 v1.2 的基础上进行了核心稳定性和部署兼容性的修复：
1. **彻底修复 `add_days` 崩溃 Bug**：增加了对所有网络请求返回值的严格校验，在遭遇 IP 封禁或风控时平滑处理，不再导致程序异常崩溃。

## 🚀 如何在 NAS / 服务器上部署 (推荐)

本项目已支持 Docker 容器化部署，极度推荐在群晖、威联通等 NAS 或者是 Linux 云服务器上运行，不仅干净且支持 7x24 小时挂机。

### 1. 准备账号文件
在你的 NAS 或服务器本地新建一个目录（例如 `/volume1/docker/pikpak`），并在里面新建一个文本文件命名为 `emails.txt`。
在里面填入你的微软邮箱账号和密码，格式如下（每行一个）：
```text
your_email1@outlook.com----your_password1
your_email2@outlook.com----your_password2

```

### 2. 拉取并运行 Docker 镜像

通过 SSH 终端或 NAS 的任务计划程序，执行以下命令：

```bash
docker run -d \
  --name pikpak-inviter \
  --restart unless-stopped \
  -p 8081:8081 \
  -v /你的实际路径/emails.txt:/app/emails.txt \
  ghcr.io/workerspages/pikpak-inviter:latest

```

*(⚠️ 请注意将 `-v` 挂载参数中的 `/你的实际路径/` 替换为你刚刚创建 `emails.txt` 的绝对路径)*

### 3. 开始使用

容器启动后，在同一局域网内的浏览器中输入：
👉 `http://<你NAS的IP地址>:8081`

即可打开 PyWebIO 的邀请控制台。填入你的 PikPak 邀请码和卡密即可自动开始运行。

## Q:这个项目真的是得到  PikPak VIP吗？

A: 从技术原理和脚本逻辑来看，**这个项目在理论上确实是为了获取 PikPak 的 VIP（会员天数）而编写的，但现实中它的有效性非常有限，且伴随着极高的失效概率和账号风险。**

我们可以从以下几个维度来客观分析这个脚本“到底能不能得到 VIP”：

### 1. 它是如何运作的？（核心原理）

这个脚本本质上是一个“自动化薅羊毛”的作弊工具（刷邀请脚本）。
PikPak 官方有一个“引荐奖励计划”（邀请好友注册，双方得 VIP 天数）。这个脚本通过以下流程作弊：

* 模拟大量不同的“假手机/假设备”（生成随机的 `device_id` 和 IP）。
* 读取你准备好的微软邮箱账号（`emails.txt`）。
* 自动向 PikPak 发起注册请求，并利用 POP3 协议自动登录微软邮箱读取 6 位数验证码。
* 注册成功后，自动填入你大号的**邀请码**。
* PikPak 服务器认为你成功邀请了一个“新用户”，从而给你的大号发放 VIP 奖励（通常是几天）。

### 2. 它真的能一直有效吗？（现实限制）

**答案是：极其不稳定，且大概率会很快失效。**
你在使用时会面临以下几个难以逾越的障碍：

* **官方极其严厉的风控（反作弊系统）：** PikPak 作为网盘服务商，防白嫖的机制非常严格。脚本的 UI 提示里原作者自己都写了：*“随用随充次日会员会掉，邀请超50人充不上需要换号，多刷无效。”* 这说明 PikPak 官方会在后台定期扫号，一旦发现你是通过同一个 IP 段、或者同一批批量注册的微软邮箱刷的邀请，**第二天就会把你的 VIP 回收，甚至直接封禁你的大号。**
* **算法写死，极易过期：** 脚本里有一段 `get_sign` 函数，里面写死了 10 个 MD5 的 `salt`（盐值，比如 `KHBJ07an7ROXDoK7Db`）。这是逆向破解了 PikPak 某一个旧版本 App 的签名算法。一旦 PikPak 更新了客户端算法，这个脚本发出的所有请求都会被直接拦截，全部报错。
* **邮箱资源枯竭：** 脚本需要源源不断的微软邮箱（Outlook/Hotmail）。现在微软对批量注册邮箱打击也很严，你需要花钱去购买这些“白号”，如果买到的号已经被 PikPak 标记为黑产邮箱，脚本跑断腿也刷不成功。
* **安全验证拦截：** 脚本中调用的 `[https://user.mypikpak.com/v1/shield/captcha/init](https://user.mypikpak.com/v1/shield/captcha/init)` 是 PikPak 的验证码接口，一旦触发风控，官方会弹出图形滑块验证码或谷歌验证码（reCAPTCHA），这个纯 API 脚本是无法绕过复杂图形验证码的，就会一直报错。

### 总结

**能得到吗？**
在算法没失效、邮箱没被拉黑、官方还没来得及封号的“空窗期”里，**确实能刷到几天的临时 VIP**。

**值得用吗？**
**非常不建议依赖它。** 这是一场猫鼠游戏，官方稍微一改接口，代码就报废了。更严重的是，你辛辛苦苦存在 PikPak 大号里的文件，可能会因为“恶意刷邀请违反用户协议”而被**连坐永久封号**，导致数据全部丢失。

如果你只是出于学习 Python 自动化、API 逆向分析和 Docker 部署的目的，这是一个很好的学习案例（涉及到并发、网络请求、加密签名、邮件解析）；但如果是为了长久使用 PikPak 服务，建议还是直接购买官方会员更安全稳定。
